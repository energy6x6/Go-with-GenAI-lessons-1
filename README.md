# Домашнє завдання · Урок 1 (Go + GenAI)

Цей репозиторій — готовий каркас для домашнього завдання. Частина завдань
перевіряється **автоматично** через GitHub Actions при кожному пуші чи
Pull Request: тести запускаються самі, вам не потрібно нічого налаштовувати
вручну — досить запушити код у гілку `main` або відкрити PR.

Перевірити статус можна у вкладці **Actions** вашого репозиторію на GitHub.

## Завдання 1 — Встановіть Go та свій ШІ-інструмент

*Не перевіряється автоматично — здається окремо викладачу.*

- Встановіть Go з [go.dev](https://go.dev) і перевірте командою `go version`.
- Встановіть обраний ШІ-інструмент: Copilot, Cursor, Claude Code або Crush.
- Відкрийте редактор, створіть тестовий файл і переконайтеся, що ШІ-асистент реагує.
- Зробіть скриншот, що показує редактор, панель ШІ та вивід `go version`.

---

## Завдання 2 — Програма привітання: ви проти ШІ

**Перевіряється автоматично тестами `greet/greet_test.go`.**

1. Відкрийте `greet/greet.go` і реалізуйте функцію самостійно, **вручну**,
   без допомоги ШІ:

   ```go
   func Greet(name string) string
   ```

   Вимоги до поведінки (їх перевіряють тести):
   - для `"Alice"` повертає `"Hello, Alice! Welcome to Go."`
   - для порожнього рядка `""` повертає `"Hello, stranger! Welcome to Go."`
   - для імені з пробілами на краях (наприклад, `"  Bob  "`) пробіли
     обрізаються: `"Hello, Bob! Welcome to Go."`

2. Закомітьте цю ручну версію.
3. Потім попросіть ШІ-асистента написати ту саму функцію з нуля в окремій
   гілці чи коміті.
4. Порівняйте обидві версії та додайте до `README.md` короткий звіт
   (3–5 речень): що ШІ зробив краще, а що — гірше?

Запустити тести локально:

```bash
go test ./greet/... -v
```

CLI можна запустити так:

```bash
go run ./cmd/greet Alice
# Hello, Alice! Welcome to Go.
```

### Короткий звіт: ручна версія проти AI

Ручна версія була простішою для контролю, бо я точно бачив, як обробляється
порожнє ім'я та обрізання пробілів. AI-версія швидко запропонувала готову
структуру CLI з `os.Args` і зрозумілим повідомленням про використання, що
зекономило час. Найкраще AI впорався з шаблонним кодом і поясненням рішення,
але його результат все одно потрібно перевіряти тестами та `gofmt`. Гірше те,
що AI може не знати точних вимог автотестів, якщо їх явно не показати в prompt.

## Завдання 3 — Створіть репозиторій курсу на GitHub

**Частково перевіряється автоматично** (кроком `Перевірка структури
репозиторію` у CI).

- Створіть публічний репозиторій на GitHub, присвячений цьому курсу.
- Додайте окрему теку для кожного заняття (наприклад, `lesson-01/`,
  `lesson-02/`) — вміст цієї теки й покладіть у відповідну теку.
- Закомітьте сьогоднішні програми Hello World і привітання.
- Додайте короткий `README.md` з поясненням, як запустити кожну програму.
- Переконайтеся, що вкладка **Actions** показує зелену галочку ✅.

Додаткові приклади з уроку 1:

```bash
go run ./lesson-01/hello
go run ./lesson-01/greet Alice
```

## Завдання 4 (бонус) — CLI-конвертер валют

**Перевіряється автоматично тестами `converter/converter_test.go`.**

Реалізуйте функцію в `converter/converter.go`:

```go
func ConvertCurrency(amount float64, rate float64) (float64, error)
```

Вимоги:
- повертає `amount * rate`;
- повертає помилку (`error`), якщо `amount` від'ємний;
- повертає помилку, якщо `rate` від'ємний або дорівнює нулю.

Спробуйте спершу написати промпт для ШІ так, як вчили на занятті —
вкажіть версію Go, точну сигнатуру функції та очікувану обробку помилок —
і порівняйте згенерований код із вимогами тестів.

Запустити тести локально:

```bash
go test ./converter/... -v -cover
```

CLI:

```bash
go run ./cmd/converter 100 0.91
# 100.00 = 91.00
```

## Що саме перевіряє CI (GitHub Actions)

Конвеєр `.github/workflows/tests.yml` на кожен push/PR виконує чекліст
із заняття «Розпізнавання неідіоматичного коду»:

| Крок                        | Що перевіряє                                             |
|------------------------------|-----------------------------------------------------------|
| `gofmt -l .`                 | Код відформатовано за стандартом Go                       |
| `go vet ./...`                | Немає підозрілих конструкцій (типові помилки компілятора) |
| `go test ./... -v -cover`     | Уся логіка проходить тести з покриттям                    |
| `go build ./...`              | Проєкт компілюється без помилок                            |
| Перевірка структури репозиторію | Наявні `README.md`, `greet/greet.go`, `converter/converter.go` |

Якщо будь-який крок впаде — перевірка в Pull Request стане червоною ❌,
і ви побачите точну причину в логах кроку.
